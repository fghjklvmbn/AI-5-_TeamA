MemoryPal 프로젝트 결과 발표 대본
예상 발표 시간: 약 10~12분

============================================================
슬라이드 1. 표지
============================================================

안녕하세요. AI휴먼 A팀의 MemoryPal 프로젝트를 소개하겠습니다.

MemoryPal은 단순히 질문에 답하는 챗봇이 아니라, 사용자의 이전 대화와 기록을 기억하고 다시 연결해 주는 맞춤형 AI 상담 비서입니다. 이번 프로젝트에서는 기억, RAG, 자화상, 음성 대화, 그리고 운영 관리 기능까지 하나의 서비스로 구현했습니다.


============================================================
슬라이드 2. 목차
============================================================

발표는 프로젝트를 시작한 배경과 목표를 먼저 설명하고, 팀 구성과 개발 절차, 전체 시스템 구조를 살펴보겠습니다. 이후 사용자와 관리자 기능을 실제 화면 중심으로 소개하고, 마지막으로 핵심 기능의 작동 흐름과 자체 평가를 말씀드리겠습니다.


============================================================
슬라이드 3. 프로젝트 개요
============================================================

기존 대화형 AI의 가장 큰 한계는 대화가 끝나면 이전 내용을 자연스럽게 이어 가지 못한다는 점이었습니다. 같은 사용자가 다시 찾아와도 매번 처음 만나는 것처럼 반응하면 정서적 동반자라는 경험을 만들기 어렵습니다.

이를 해결하기 위해 MemoryPal에는 세션 안에서 사용하는 단기기억과 여러 세션에서 활용하는 장기기억을 도입했습니다. 여기에 첨부 문서를 의미 기반으로 검색하는 RAG를 결합해, 답변이 사용자의 실제 기록과 문서 근거를 활용하도록 했습니다.

또한 누적된 대화를 바탕으로 사용자의 특징을 두 글자 제목과 설명으로 보여 주는 자화상 기능을 추가했습니다. 즉, MemoryPal의 핵심은 기억을 통해 대화를 이어 가고, 사용자가 자신의 모습을 다시 이해하도록 돕는 것입니다.


============================================================
슬라이드 4. 팀 구성 및 역할
============================================================

팀은 총 네 명으로 구성했습니다. 팀장은 전체 일정과 기능 통합, 모델 분석과 발표를 담당했습니다. 백엔드 영역에서는 RAG, 벡터 검색, API 구조를 구현했고, 프론트엔드 영역에서는 사용자 화면 구조와 기능 연동, 테스트를 담당했습니다. 데이터 영역에서는 데이터 수집과 정제, 분석과 시각화를 진행했습니다.

각자 맡은 영역은 달랐지만, 실제 서비스에서는 기능이 서로 연결되어야 했기 때문에 API 규격과 데이터 흐름을 지속적으로 맞추며 개발했습니다.


============================================================
슬라이드 5. 프로젝트 수행 절차
============================================================

개발은 한 번에 모든 기능을 붙이는 방식이 아니라 단계적으로 진행했습니다. 먼저 STT, LLM, TTS 같은 개별 AI 서버의 동작을 확인했고, 다음으로 사용자 화면과 Gateway, 인증 기능을 연결했습니다.

그 위에 세션 기억, 장기기억, 문서 RAG를 추가한 뒤, 마지막 단계에서 개인화 음성, 관리자 모니터링, 배포 스크립트와 오류 처리를 보완했습니다. 특히 후반에는 기능 구현뿐 아니라 서비스 간 형식 차이와 장애 상황을 정리하는 데 집중했습니다.


============================================================
슬라이드 6. 시스템 구성 소개
============================================================

전체 구조는 네 부분으로 나눠 볼 수 있습니다. 사용자가 직접 접하는 애플리케이션, 모든 요청을 조율하는 Gateway, AI와 음성을 처리하는 모델 서버, 그리고 사용자 데이터와 기억을 저장하는 데이터 영역입니다.

이후 슬라이드에서는 전체 구조, 프론트엔드, 백엔드 AI 파이프라인, 데이터와 보안 순서로 설명하겠습니다.


============================================================
슬라이드 7. 애플리케이션 구조
============================================================

사용자 앱과 관리자 화면은 Gateway를 통해서만 서비스에 접근합니다. Gateway는 로그인과 권한 확인, 채팅 세션, 기억 검색, RAG, 음성 요청을 한곳에서 조율합니다.

음성 입력은 STT 서버로, 답변 생성은 LLM 서버로, 음성 합성은 TTS 서버로 전달합니다. 첨부파일과 개인화 음성은 Archive 서비스에서 별도로 관리합니다. 이렇게 서버의 역할을 나누면 한 서비스에 문제가 생겨도 전체 기능이 함께 중단되는 위험을 줄일 수 있습니다.

또한 모델 서버나 저장소가 변경되더라도 사용자 앱은 Gateway와의 동일한 규격만 유지하면 되도록 설계했습니다.


============================================================
슬라이드 8. 프론트엔드 기술 스택
============================================================

프론트엔드는 Expo와 React Native Web을 사용해 웹을 중심으로 구현하면서도 모바일 환경으로 확장할 수 있도록 구성했습니다.

사용자 화면에는 메인, 채팅, 기억, 자화상, 설정 메뉴가 있고, 관리자 화면에는 서비스 자원, 트랜잭션, 작업 상태, 사용자 이용 지표가 있습니다.

메뉴를 이동해도 진행 중인 채팅이나 모델 다운로드 상태가 사라지지 않도록 상태를 유지했고, 모바일 화면에서는 입력창과 캐릭터 선택 영역이 겹치지 않도록 별도의 반응형 배치를 적용했습니다.


============================================================
슬라이드 9. AI·음성 백엔드
============================================================

음성 입력은 사용자가 녹음을 시작하고 끝낼 때까지의 내용을 하나로 묶어 Whisper Turbo로 전달합니다. 짧은 단위로 계속 잘라 보내는 방식보다 문장 전체의 맥락을 인식하기 쉽다는 장점이 있습니다.

대화는 사용자가 선택한 모델 또는 MemoryPal 전용 모델이 처리하고, 답변 음성은 Qwen3-TTS가 생성합니다. 개인화 음성과 기본 음성은 Archive에서 관리하며, 계정별 소유권을 확인한 뒤 사용할 수 있습니다.

중요한 점은 음성 서버에 장애가 생겨도 텍스트 채팅은 계속 사용할 수 있도록 기능의 경계를 분리했다는 것입니다.


============================================================
슬라이드 10. 데이터 저장과 보안
============================================================

Gateway 저장소에는 사용자, 채팅 세션, 메시지, 장기기억, 첨부파일 소유권을 기록합니다. 음성 프로필과 관련 메타데이터는 Archive 저장소에서 별도로 관리합니다.

사용자 비밀번호는 원문으로 저장하지 않고 솔트 해시로 처리하며, 요청은 JWT 인증을 거칩니다. 첨부파일과 음성에는 크기 제한을 두었고, 인증정보와 같은 민감한 내용은 장기기억으로 저장되지 않도록 차단했습니다.

또한 실제 비밀값은 소스 코드에 넣지 않고 버전관리에서 제외된 환경 설정과 런타임 비밀 저장소에서 관리합니다.


============================================================
슬라이드 11. 사용자 기능 구성
============================================================

사용자 기능은 메인, 채팅, 기억, 자화상, 설정의 다섯 영역으로 구성했습니다. 이제부터는 각 화면에서 사용자가 실제로 무엇을 할 수 있는지 설명하겠습니다.


============================================================
슬라이드 12. 메인 화면
============================================================

메인 화면은 사용자가 가장 빠르게 대화를 시작할 수 있도록 구성했습니다. 현재 사용 중인 모델을 항상 확인하고 직접 선택할 수 있으며, 중앙의 시작 버튼으로 음성 녹음을 시작합니다.

녹음 중에는 현재 음성을 인식하고 있다는 상태를 화면에 표시합니다. 사용자는 내부 서버 구조를 알 필요 없이 녹음을 마치면 STT, LLM, 필요할 경우 TTS까지 연결된 결과를 받을 수 있습니다.


============================================================
슬라이드 13. 채팅 및 하이브리드 화면
============================================================

채팅은 일반 채팅, 실시간 대화, 하이브리드의 세 가지 모드를 지원합니다. 일반 채팅은 기존 메신저처럼 텍스트와 파일을 사용합니다.

하이브리드 모드에서는 한쪽에 캐릭터를 보여 주고 다른 쪽에는 대화 내용을 함께 표시합니다. 사용자는 텍스트와 음성을 모두 사용할 수 있고, 설정에 따라 답변 음성도 재생할 수 있습니다.


============================================================
슬라이드 14. 실시간 음성 대화
============================================================

실시간 모드는 화면의 캐릭터와 음성으로 대화하는 경험에 초점을 맞췄습니다. 사용자가 캐릭터를 선택했을 때만 해당 자원을 불러와 불필요한 사용을 줄였습니다.

사용자의 음성은 기존 STT 흐름을 재사용하고, 생성된 답변은 TTS로 자동 재생됩니다. 캐릭터는 대기 중에는 자연스럽게 움직이고, 답변 음성에 맞춰 입 모양이 변하도록 구현했습니다.


============================================================
슬라이드 15. 기억 화면
============================================================

기억 화면에서는 AI가 저장한 장기기억을 사용자가 직접 확인할 수 있습니다. 기억의 종류별로 분류하거나 검색할 수 있고, 필요한 기억을 사용자가 직접 추가할 수도 있습니다.

모든 대화가 곧바로 장기기억이 되는 것은 아닙니다. 현재 세션의 대화는 단기기억으로 유지하고, 여러 세션에서 반복되는 선호나 프로필 정보처럼 지속성이 높은 내용만 조건에 따라 장기기억 후보로 올립니다. 사용자가 ‘기억해 줘’라고 명확하게 요청한 내용은 즉시 저장할 수 있습니다.


============================================================
슬라이드 16. 자화상 화면
============================================================

자화상은 누적된 대화를 분석해 사용자의 특징을 두 글자 제목과 한 문단의 설명으로 보여 주는 기능입니다.

대화가 너무 적으면 결과가 부정확해질 수 있기 때문에 최소 세션 수, 대화 턴 수, 글자 수 기준을 모두 충족해야 분석할 수 있도록 제한했습니다. 기준이 부족한 경우에는 어떤 항목이 충족됐고 무엇이 부족한지 구분해서 안내합니다.

분석이 완료되면 사용자는 단순한 통계가 아니라, 자신의 대화에서 반복된 특징을 하나의 설명으로 확인할 수 있습니다.


============================================================
슬라이드 17. 기능 설정
============================================================

설정 화면에서는 대화 경험을 사용자 취향에 맞게 조절할 수 있습니다. 존댓말과 반말, 생각 모드, 응답 음성, 기본 대화 모드와 같은 항목을 설정할 수 있습니다.

생각 모드는 모델이 실제로 지원하는 기능을 확인한 뒤 사용할 수 있는 항목만 활성화합니다. 따라서 지원하지 않는 모델에서 의미 없는 설정을 선택하는 문제를 줄였습니다.


============================================================
슬라이드 18. 개인화 음성과 모델 관리
============================================================

개인화 음성 화면에서는 사용자가 자신의 응답 음성을 등록하고 선택할 수 있습니다.

모델 관리 화면에서는 Hugging Face 기반으로 모델을 검색하고, LM Studio에 다운로드한 뒤 로드할 수 있습니다. 다운로드 진행 상황은 다른 탭으로 이동해도 유지되며, 실패한 경우에는 재시도할 수 있습니다.

서버 자원을 보호하기 위해 사용자별 추가 모델 용량과 모델 크기, 동시에 로드할 수 있는 모델 수에도 제한을 적용했습니다.


============================================================
슬라이드 19. 개인정보 설정
============================================================

개인정보 설정에서는 계정 정보를 수정하거나 회원 탈퇴를 진행할 수 있습니다. 사용자별 세션, 기억, 첨부파일, 음성 데이터는 계정 기준으로 분리합니다.

회원 탈퇴처럼 복구가 어려운 작업은 별도의 확인 단계를 거치게 해 실수로 데이터가 삭제되는 것을 방지했습니다.


============================================================
슬라이드 20. 관리자 기능 구성
============================================================

관리자 기능은 서비스를 실제로 운영할 때 필요한 정보에 초점을 맞췄습니다. 전체 상태를 보는 메인 화면, 서버 자원, 요청별 트랜잭션과 작업 상태, 사용자별 이용 지표로 구성했습니다.


============================================================
슬라이드 21. 메인 및 서비스 자원
============================================================

관리자 메인 화면에서는 전체 사용자 수와 요청 현황, 서비스 상태를 빠르게 확인할 수 있습니다.

서비스 자원 화면에서는 STT, LLM, TTS, Gateway, Archive 서버의 CPU와 메모리 사용량을 확인합니다. LLM 서버는 GPU 사용률과 VRAM의 전체 용량, 사용량, 남은 용량까지 함께 수집합니다.

수집된 값과 서비스 동작 여부를 기준으로 상태를 초록색, 노란색, 빨간색으로 구분해 운영자가 문제를 빠르게 발견할 수 있게 했습니다.


============================================================
슬라이드 22. 트랜잭션 및 작업 상태
============================================================

한 번의 음성 대화는 STT, LLM과 RAG, TTS처럼 여러 서비스를 거칩니다. 기존에는 오류가 나면 어느 단계에서 문제가 발생했는지 찾기 어려웠습니다.

이를 개선하기 위해 하나의 사용자 요청을 공통 트랜잭션으로 묶고, 각 단계를 같은 요청 아래에서 추적하도록 했습니다. 작업 상태 화면에서는 진행 중, 완료, 실패 여부와 단계별 처리 시간을 확인할 수 있습니다.

또한 모델 로드와 생성 과정에서 발생하는 LM Studio 로그도 가공해, 단순한 원문 로그가 아니라 어떤 모델이 어떤 작업을 처리했는지 알아보기 쉽게 표시합니다.


============================================================
슬라이드 23. 사용자별 이용 지표
============================================================

사용자별 이용 지표 화면에서는 계정별 로그인, 채팅, 음성, 기억, 자화상 이용 현황을 확인할 수 있습니다.

이 화면의 목적은 사용자의 대화 내용을 감시하는 것이 아니라, 어떤 기능이 실제로 사용되고 있고 어디에서 오류가 많이 발생하는지 운영 관점에서 파악하는 것입니다.


============================================================
슬라이드 24. 시연 시나리오
============================================================

시연은 네 가지 흐름으로 진행하겠습니다. 먼저 음성 입력부터 답변까지 이어지는 전체 AI 파이프라인을 확인합니다. 두 번째로 캐릭터 대화에서 장기기억과 문서 RAG가 연결되는 모습을 보여 드립니다.

세 번째로 누적된 대화를 이용한 자화상 생성을 확인하고, 마지막으로 사용 모델을 변경해도 MemoryPal의 답변 경험이 유지되는지 보여 드리겠습니다.


============================================================
슬라이드 25. 페르소나 없음 상태의 기본 챗봇
============================================================

먼저 페르소나를 ‘없음’으로 설정한 기본 챗봇의 흐름입니다.

사용자가 텍스트, 음성, 첨부파일과 함께 질문하면 Gateway가 계정과 세션, 권한을 확인합니다. 최근 10턴으로 현재 대화 문맥을 구성하고, 장기기억과 첨부 문서에서 질문과 의미적으로 가까운 내용을 검색합니다.

검색된 근거는 사용자가 선택한 일반 모델로 전달됩니다. 이때 특정 캐릭터나 동반자 역할을 강제로 적용하지 않고, 모델이 아는 지식과 제공된 근거를 구분해 답변하도록 합니다.

답변과 문맥은 현재 세션에 저장되고, 조건을 충족한 정보만 장기기억 후보가 됩니다. 화면에는 텍스트를 먼저 표시하고 검색 출처는 접힌 영역으로 제공합니다.


============================================================
슬라이드 26. 어댑티브 MemoryPal 페르소나
============================================================

다음은 기본 MemoryPal 페르소나의 작동 방식입니다. 핵심은 기반 모델이 바뀌어도 서비스의 정체성과 답변 원칙을 유지하는 것입니다.

사용자의 요청, 현재 대화 문맥, 말투와 페르소나 설정을 먼저 모은 뒤 MemoryPal 응답 계약을 적용합니다. 이 계약에는 질문에 먼저 답하기, 기억과 검색 근거 구분하기, 요청한 형식 지키기, MemoryPal이라는 정체성 유지하기가 포함됩니다.

그다음 사용자가 선택한 모델을 호출하고, 빈 답변이나 형식 문제가 있는지 확인합니다. 실패하면 같은 정체성과 규칙으로 다시 시도합니다.

또한 사용자가 인사만 입력한 경우에는 모델을 호출하지 않고 ‘안녕하세요 MemoryPal입니다. 무엇을 도와드릴까요?’라는 고정 인사를 즉시 반환합니다.


============================================================
슬라이드 27. RAG와 기억의 연결
============================================================

이 슬라이드는 RAG와 기억이 실제 답변에 어떻게 사용되는지를 보여 줍니다.

먼저 현재 세션의 최근 대화로 문맥을 만들고, 장기기억과 업로드 문서를 의미 기반 벡터 검색으로 조회합니다. 검색된 내용은 서로 섞어서 저장하는 것이 아니라 세션 기억, 장기기억, 문서 근거로 구분한 상태에서 LLM에 전달합니다.

LLM은 이 근거와 페르소나 설정을 함께 사용해 답변을 생성합니다. 대화는 우선 현재 세션에 저장하며, 반복되는 선호나 사용자 정보만 조건부로 장기기억에 저장합니다.

최종 화면에서는 답변을 먼저 보여 주고, 출처는 필요한 사용자가 확인할 수 있도록 접어서 표시합니다. 음성으로 답변할 때는 출처 주소를 읽지 않고 실제 답변 내용만 전달합니다.


============================================================
슬라이드 28. 시연 영상 안내
============================================================

지금까지 설명한 기능은 별도의 시연 영상을 통해 실제 동작 화면으로 확인할 수 있습니다. 영상에서는 기능 목록을 단순히 나열하기보다, 사용자가 질문을 입력한 뒤 각 서비스가 처리하고 결과가 화면에 나타나는 전체 흐름을 중심으로 보여 드리겠습니다.


============================================================
슬라이드 29. 자체 평가 및 마무리
============================================================

이번 프로젝트는 최소 기능 구현을 넘어서, 사용자 앱과 여러 AI 서버, 기억과 RAG, 관리자 운영 기능을 실제로 연결했다는 점에서 의미가 있습니다.

잘한 점은 팀원의 의견을 적극 반영하고, 기능 간 연결에서 발생한 문제를 하나씩 해결해 실제로 동작하는 MVP를 완성한 것입니다. 반면 초기에는 통합 난이도와 일정을 충분히 예측하지 못해 후반 작업이 집중됐고, 캐릭터 립싱크와 응답 속도처럼 더 개선할 부분도 남아 있습니다.

앞으로는 실제 사용자 평가와 응답 시간 측정, 캐릭터 표현 개선을 이어 갈 예정입니다. MemoryPal이 단순히 답하는 AI를 넘어, 사용자의 기록을 안전하게 기억하고 필요한 순간에 다시 연결해 주는 서비스가 되는 것이 최종 목표입니다.

이상으로 발표를 마치겠습니다. 감사합니다.
